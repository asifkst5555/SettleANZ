# Final Pre-Deployment SEO Audit — SettleANZ

**Date:** 2026-05-31
**Auditor:** Senior Technical SEO Engineer
**Scope:** 14-phase pre-deployment audit covering architecture, metadata, canonical, H1, OG, structured data, images, Core Web Vitals, sitemap, robots.txt, security, internal linking, and indexing readiness.

---

## Executive Summary

**Deployment Readiness: NOT READY — 7 high-priority issues must be addressed before production deployment.**

The core SEO architecture is sound (single layout, dynamic metadata, pagination-aware titles/canonicals), but there are significant production configuration gaps and performance optimizations needed.

---

## Critical Issues (Must Fix Before Deployment)

### C1. APP_URL set to development domain

**File:** `.env` (line 5)
**Current:** `APP_URL=http://settleanz.test`
**Required:** `APP_URL=https://settleanz.com`

**Impact:** Every URL generated by `route()`, `asset()`, `config('app.url')` will use the incorrect domain. This affects:
- Sitemap URLs (`SeoAssetController.php:14-25`)
- Canonical URLs (`layouts/app.blade.php:13`)
- JSON-LD Organization URL and logo URL (`BlogController.php:149,152`, `layouts/app.blade.php:63,66`)
- Open Graph URLs (`layouts/app.blade.php:37`)
- All `asset()` calls for CSS, JS, images
- Storage disk URLs (`config/filesystems.php:44`)

### C2. Missing www-to-non-www redirect

**File:** `public/.htaccess`
**Current:** No redirect rules for www canonicalization
**Impact:** `https://www.settleanz.com` resolves without redirecting to `https://settleanz.com`, causing duplicate content.

**Fix:**
```apache
RewriteCond %{HTTP_HOST} ^www\.(.*)$ [NC]
RewriteRule ^ https://%1%{REQUEST_URI} [L,R=301]
```

### C3. Missing HTTPS redirect

**File:** `public/.htaccess`
**Current:** No HTTP→HTTPS redirect
**Impact:** `http://settleanz.com` serves non-secure content. Users can access the site over unencrypted HTTP.

**Fix:**
```apache
RewriteCond %{HTTPS} off
RewriteRule ^ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]
```

### C4. APP_ENV and APP_DEBUG not set for production

**File:** `.env` (lines 3-4)
**Current:**
```
APP_ENV=local
APP_DEBUG=true
```
**Required:**
```
APP_ENV=production
APP_DEBUG=false
```
**Impact:** Debug mode exposes sensitive information, error traces, and environment variables. Search engines may index debug output.

## High Priority Issues (Fix Before Launch)

### H1. No lazy loading on 39 of 41 images

**Impact:** 95% of images load eagerly, including below-the-fold images. This increases Largest Contentful Paint (LCP) and initial page weight.

**Files affected:**
- `resources/views/home.blade.php` — empathy cards, founder photo, testimonials, blog cards, partner logos
- `resources/views/guides/new-to-australia.blade.php` — hero, guide images
- `resources/views/guides/settlement-services.blade.php` — service images
- `resources/views/blog/index.blade.php` — blog hero and cards
- `resources/views/about.blade.php` — about image
- `resources/views/contact.blade.php` — contact image

**Fix:** Add `loading="lazy"` to all below-fold images. Hero/above-fold images should have `loading="eager"` or no attribute.

### H2. 95% of images lack explicit width/height attributes

**Impact:** Missing width/height on 39 of 41 images causes Cumulative Layout Shift (CLS) as images load and push content down.

**Only 2 images have dimensions:** Floating action icons (56x56) in `layouts/app.blade.php`.

**Fix:** Add `width` and `height` attributes to all `<img>` tags. For responsive images, use `aspect-ratio` in CSS as a fallback.

### H3. Large render-blocking CSS (196 KB site.css)

**File:** `public/site.css` — 196 KB unminified
**File:** `resources/views/layouts/app.blade.php` — ~550 lines inline chat CSS

**Impact:** Render-blocking CSS delays First Contentful Paint (FCP) and Largest Contentful Paint (LCP).

**Recommendation:**
1. Enable Vite build pipeline for site.css (currently loaded as legacy static file)
2. Extract critical CSS and inline it in `<head>`
3. Defer non-critical CSS with `media="print" onload="this.media='all'"`
4. Minify and tree-shake the legacy CSS files

### H4. Google Fonts are render-blocking

**File:** `resources/views/layouts/app.blade.php` (line 74)
**Current:** `<link href="https://fonts.googleapis.com/css2?...&display=swap" rel="stylesheet">`

**Impact:** The Google Fonts CSS file is loaded synchronously and blocks rendering, even though `display=swap` prevents FOIT.

**Fix:**
```html
<link rel="preload" href="https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600&family=Plus+Jakarta+Sans:wght@600;700&display=swap" as="style" onload="this.onload=null;this.rel='stylesheet'">
<noscript><link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600&family=Plus+Jakarta+Sans:wght@600;700&display=swap"></noscript>
```

### H5. Orphaned guide pages (Housing, Banking, Migration Services)

**Current:** Three guide pages are hidden from navigation (`visible=false`) and not linked from the footer:
- `/housing` — not in nav, not in footer
- `/banking` — not in nav, not in footer
- `/migration-services` — not in nav, not in footer. **No inbound internal links from any page.**

**Impact:** These pages are only discoverable via sitemap. Search engines may still find them, but they receive minimal link equity.

**Fix:** Either add these to the navigation/footer, or add contextual links from related pages. `/migration-services` is most critical as it has zero internal inbound links.

### H6. Sitemap missing directory listing pages

**File:** `app/Http/Controllers/SeoAssetController.php` (lines 28-45)
**Impact:** Individual directory listing pages (`/directory/{slug}`) are not included in the sitemap.

**Fix:** Add directory listing query similar to blog posts query.

### H7. Missing structured data breadcrumbs on directory pages

**File:** `resources/views/directory/show.blade.php` (lines 7-8)
**Current:** Plain `<a href="...">← Back to Directory</a>` — no BreadcrumbList schema markup.

**Impact:** Directory detail pages lack breadcrumb structured data, missing an opportunity for rich results in SERP.

**Fix:** Add `BreadcrumbList` JSON-LD schema for directory pages (Home > Directory > Listing Name).

## Medium Priority Issues

### M1. Blog index heading hierarchy skip (H1 → H3)

**File:** `resources/views/blog/index.blade.php` (lines 231, 283)
**Issue:** `<h1>` is followed directly by `<h3>` with no `<h2>` in between.

**Fix:** Change blog card titles from `<h3>` to `<h2>`, or add a section `<h2>` above the blog grid (e.g., `<h2>Latest Articles</h2>`).

### M2. Missing alt text on 10 images

**Files:**
- `layouts/app.blade.php:1124,1128` — `alt=""` on floating icons (decorative, acceptable)
- `contact.blade.php:313` — `alt=""` on contact page hero image (should have descriptive alt)
- `blog/index.blade.php:244` — `alt=""` on blog hero image (should have descriptive alt)
- `home.blade.php:1359-1363` — `alt=""` on 5 partner logo duplicates (second carousel strip is decorative, acceptable)

**Impact:** Contact and blog hero images missing descriptive alt text hurts accessibility and image SEO.

**Fix:** Add descriptive alt text to contact hero and blog hero images.

### M3. Missing twitter:site meta tag

**File:** `resources/views/layouts/app.blade.php` (lines 44-47)
**Current:** Twitter Card present (card, title, description, image) but missing `twitter:site`.

**Fix:** Add `<meta name="twitter:site" content="@SettleANZ">`.

### M4. Static /public/robots.txt overrides dynamic route

**File:** `public/robots.txt` (2 lines: `User-agent: * / Disallow:`)
**Route:** `app/Http/Controllers/SeoAssetController.php:56-67` (dynamically generates: Allow /, Disallow /admin, Sitemap URL)

**Issue:** The static file is served before the dynamic route if the web server is not configured to pass `.txt` files to Laravel.

**Fix:** Delete the static `public/robots.txt` file to ensure the dynamic route is always used.

### M5. No breadcrumb schema on blog index or directory index pages

**Impact:** The blog listing and directory listing pages have no `BreadcrumbList` schema markup. Only blog articles have breadcrumb schema.

**Fix:** Add `BreadcrumbList` schema to collection/listing pages.

### M6. No preload for critical hero images

**Impact:** Hero images (LCP candidates) are loaded without priority hints.

**Fix:** Add `<link rel="preload" as="image" href="...">` for hero images on each page (home hero video, blog hero, etc.).

### M7. No `rel="noopener"` on external links

**Current:** External links use `rel="noreferrer"` but not `rel="noopener"`.

**Impact:** While modern browsers treat `noreferrer` as implying `noopener`, explicitly including both provides maximum compatibility.

**Fix:** Change all `rel="noreferrer"` to `rel="noopener noreferrer"` on `target="_blank"` links.

## Low Priority Issues

### L1. DirectoryController uses hardcoded metadata instead of PageSeo

**File:** `app/Http/Controllers/DirectoryController.php` (lines 22-23)
**Impact:** Admin SEO manager cannot edit directory listing page SEO metadata.

### L2. No AVIF image format support

**Impact:** AVIF provides 20-30% better compression than WebP. Not critical but a missed optimization.

### L3. Contact page hero image uses PNG format (240 KB+)

**File:** `resources/views/contact.blade.php` (line 313)
**Image:** `media/contact/contact.png`

**Impact:** PNG is larger than WebP/AVIF. Recommend converting to WebP.

### L4. No dns-prefetch or prefetch for common third-party resources

**Current:** Only `preconnect` for Google Fonts. Missing:
- `dns-prefetch` for analytics, CDN, or API endpoints
- `prefetch` for likely-next-page resources

### L5. Inline chat CSS (~550 lines) loaded on every page

**File:** `resources/views/layouts/app.blade.php` (lines 78-855)
**Impact:** ~550 lines of CSS for the AI chat assistant is inlined on every page, even when chat is not visible.

### L6. Admin JS scripts not deferred

**File:** `resources/views/admin/layouts/app.blade.php` (lines 164-168)
**Impact:** Admin pages load render-blocking JS (modal.js, notifications.js, admin-form-handler.js).

## Final Verdict

**Website is NOT SEO-ready for production deployment.**

**4 critical issues** must be resolved before deployment (APP_URL, APP_ENV, HTTPS, WWW redirect). These will break all canonical URLs, sitemap URLs, and JSON-LD URLs, and expose debug information.

**7 high-priority issues** should be resolved before launch to ensure optimal search performance, Core Web Vitals scores, and indexability.

Once the critical and high-priority issues are addressed, the site has a solid SEO foundation with:
- Proper pagination-aware metadata
- Unique titles and descriptions per page
- Self-canonicalizing URLs
- Complete Open Graph implementation
- JSON-LD structured data for blog articles
- Database-backed SEO management via admin panel
- AI-assisted SEO metadata generation

**Estimated time to deployment readiness:** 1-2 days for critical/high issues
**Estimated time to full optimization:** 2-4 weeks
